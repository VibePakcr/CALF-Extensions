# Local Pack Tools · Repository 팩 — 0.1.0-preview.1

[English](PACKS_GUIDE.md)

기존 CALF 기록이나 호스트 설정을 바꾸지 않고 로컬 확장의 버전을 관리하는 개발 프리뷰입니다. Repository inspect는 로컬 Git 저장소를 읽고 파일 버전 근거가 담긴 프로젝트 지도를 저장합니다. 프로젝트의 애플리케이션 테스트를 대신 실행하지는 않습니다. Python 3.10 이상·Git 2.43 이상이 필요하며, 이 모드에는 네이티브 코어·SDK·모델·전역 pip 설치·상주 서비스가 필요하지 않습니다.

## 시작하기

1. SHA256SUMS와 다운로드한 ZIP의 해시를 대조합니다. Local Pack Tools만 새 폴더에 풀고 Repository 팩은 ZIP 상태로 둡니다.
2. 도구에 포함된 `docs/REPOSITORY_PACK_KR.md`에 따라 실제 Python·Git 실행 파일을 선택하고, 별도 저장소에서 준비·호환성 확인·검수·활성화를 진행합니다.
3. 원본 저장소 밖의 별도 기록 폴더를 지정해 작업을 연결하고 한 번 실행합니다. 검사 영수증을 확인한 뒤 저장된 지도를 내보냅니다. 원본은 읽기 전용이며, 소스 본문은 요청한 경우에만 내보냅니다.

명령은 압축을 푼 도구 폴더에서 실행합니다. Windows는 `python -X utf8 -B -m calf_extensions.packs.cli`, macOS·Linux는 `python3 -B -m calf_extensions.packs.cli`를 사용합니다. 절대 경로를 지정하고 Windows 저장소 경로는 `C:\CP`처럼 짧게 잡으세요. 경로 한도를 넘으면 실행을 거절하며 OS 설정은 바꾸지 않습니다.

## 업데이트와 복구

팩을 업데이트하려면 다른 버전을 준비·검수한 뒤 `status`에서 현재 해시를 읽어 활성화합니다. 복귀는 보존된 검수 잠금 정보를 선택하며 이후 작업에만 적용됩니다. 기존 작업은 원래 팩·실행기·도구의 해시와 영수증을 유지합니다. 참조 중인 버전이나 실행 파일은 지우지 마세요.

관리기 업데이트는 새 도구를 옆 폴더에 풀고 동일한 `--home` 저장소를 지정하는 방식입니다. 이전 도구 폴더에서 실행하면 관리기를 되돌릴 수 있습니다. 저장소·작업 기록·설정이나 실행 중인 파일을 교체하지 마세요. 이번에는 같은 v1 규약을 쓰는 차기 버전 시험용 파일로 호환성을 확인했으며, 임의의 미래 버전까지 보증하지는 않습니다.

중단된 준비·활성화는 `recover`로 상태를 확인합니다. 실제 상태를 확인한 뒤 `recover --acknowledge OPERATION_ID`로 확인된 처리 기록만 마무리합니다. 작업을 재제출하거나 증거를 다시 쓰지 않습니다. 실행은 시작됐지만 영수증이 없으면 대조가 끝날 때까지 UNKNOWN으로 남습니다.

## 확인한 범위

macOS arm64·Windows x86_64·Debian x86_64에서 각각 관리기 계약 검사 20개, 팩 두 버전의 검수 각 20개(건너뛴 검사 0개), 설치·복구 흐름 12개와 관리기 교체·복귀 검사 5개를 통과했습니다. 활성화 전후의 실제 프로세스 종료, 준비 중단 복구, 시간 초과 시 소유 자식 프로세스 정리, CJK 오프라인 내보내기, 오래된 해시 거절과 원본·영수증 보존을 확인했습니다. 영수증 유실은 명시적인 모의 실패 사례입니다. 플랫폼 버전과 파일 해시는 PACKS_VERIFICATION.json에 있습니다.

Repository `0.1.1-preview.1` ZIP과 `update-fixture` 도구 ZIP은 업데이트 시험용이며 권장 설치판이 아닙니다. 이번 프리뷰는 도구·Repository 팩 모두 `0.1.0-preview.1`을 설치하세요. 네이티브 하네스는 1.8.7, 워크벤치는 1.9.2를 유지합니다. AI 호스트 세션 검증은 별도이며 Claude 어댑터는 macOS만 검증됐습니다. 프로세스 중단 복구와 전원 장애 보증은 구분합니다. 이번 릴리즈에서는 모델 호출이나 메모리·장시간 시험을 하지 않았습니다.

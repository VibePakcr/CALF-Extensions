**Repository 팩 0.1.1-preview.4**의 배포 ZIP을 바꾸지 않고 2026년 11월 8일 추가 검증했습니다. SHA-256은 `a2315cbbd9fc76994d6ee11c04b14f3e832d71aec9bd63d2f0dc4e63456f75fe`입니다. 이 결과를 적용하기 위해 코어나 실행 코드를 다시 설치할 필요는 없습니다. 이전 패키지와 그 안의 매뉴얼도 그대로 보관합니다.

## Windows·Linux

Windows x64·Python 3.12.10과 Debian x64·Python 3.13.5에서 각각 기록 조회 검사 21개를 건너뜀 없이 통과했습니다. 두 환경 모두 배포된 Harness 1.8.8을 사용했습니다. 새 시험용 저장소에서 이전 팩과 현재 팩을 검수하고, 업데이트·롤백·현재 버전 재선택 후에도 기존 잠금 정보가 유지되는지 확인했습니다.

운영체제마다 새로 만든 네이티브 기록 76개를 원본 참조와 대조했습니다. CJK 출력, 최근 20개 요약 밖에 있는 오래된 규칙 검색, 원본 한 건 조회, 손상된 체인 거부, 오래된 인덱스 거부와 새 폴더 재생성을 확인했습니다. 실제 네이티브 검사가 통과한 뒤 파일을 바꾸면 `UNKNOWN`으로 돌아갔습니다. 기존 파일은 Windows 744개·Linux 878개 모두 바이트까지 같았습니다. 시스템 도구를 설치하거나 사용 중인 앱을 교체하지 않고 별도 시험용 저장소와 합성 자료로 검증했습니다.

## 새 세션에서 이어가기

Codex app-server·Antigravity ACP·Claude Code의 새 세션에 이전 대화나 정답을 주지 않았습니다. 작업 폴더의 안내에는 로컬 조회 경로만 넣었습니다. 세 세션 모두 오래된 map 규칙을 찾고 원본의 순번·ID·해시를 정확히 인용했으며, 현재 판정은 `UNKNOWN`으로 구분했습니다. 해당 조회 경로로 다른 모듈 요약을 읽지는 않았습니다.

조회는 최근 모듈 요약 → 오래된 규칙 검색 → 원본 한 건 → 현재 네이티브 판정 순서였습니다. 125,216바이트의 합성 기록에서 세 세션이 받은 구조화 응답은 각각 총 8,345바이트였습니다. 호스트 지침·전송 형식·진단 출력은 제외한 수치입니다. 모듈·검색은 원본 본문 없이 메타데이터를 읽고, 원본 한 건 조회는 732바이트를 읽었습니다. 현재 판정은 무결성을 확인하려고 전체 파일의 해시를 다시 계산합니다. 토큰 절약률·전체 호스트 I/O·일률적인 속도 향상을 측정한 결과는 아닙니다.

Codex는 작업 폴더의 `AGENTS.md`를 자동으로 읽었다는 정보를 반환했습니다. Antigravity는 준비한 작업 폴더의 조회 경로를 사용했지만, 지침 파일을 어디서 읽었는지는 별도 메타데이터로 확인하지 못했습니다. Claude의 일반 Bash 시험은 정답을 찾았으나 자체 작업 폴더의 메모리 인덱스 확인과 안내 파일 읽기가 추가돼 처음의 엄격한 도구 범위 검사를 통과하지 못했습니다. 이 실패는 그대로 남겼습니다. 이후 별도 새 세션에서 Bash·디렉터리 도구 없이 임시 읽기 전용 MCP 네 개만 사용해 통과했습니다. 모델 요청 전에 연결을 확인했고 종료 후 프로세스가 남지 않았습니다.

이 MCP 어댑터는 **이번 작업 범위로 제한한 시험 연결**이며 배포 ZIP에 범용 Repository MCP 서버를 새로 넣은 것은 아닙니다. 새 GUI 세션·Claude 일반 채팅·Cowork·클라우드 세션까지 검증한 결과로 해석해서는 안 됩니다.

## 내 프로젝트에 연결하기

[로컬 기록 조회](REPOSITORY_HISTORY_KR.md)를 따라 모듈을 직접 지정하고 인덱스를 만드세요. 기존 지침을 보존하면서 Codex의 `AGENTS.md`, Antigravity의 `GEMINI.md`, Claude Code의 `CLAUDE.md` 중 사용 중인 파일에 짧은 조회 안내를 덧붙이면 됩니다. 선택한 Python·Repository 팩·인덱스·CALF 실행 파일의 위치와 다음 순서를 알려 주세요.

1. 작업에서 지목한 모듈을 고르고 `history module --module MODULE`로 요약을 읽습니다.
2. 필요한 규칙이 최근 요약에 없으면 `history search`로 찾습니다.
3. 고른 순번을 `history record`로 읽고 원본 식별자를 인용합니다.
4. 현재 판정은 `history status`로 확인합니다. Markdown에 적힌 과거 통과를 현재 완료로 처리하지 않습니다.

전체 명령은 기존 조회 안내에 있습니다. Windows에서는 `python -X utf8 -B`를 사용하세요. 경로와 모듈 범위는 사용자가 선택합니다. 모든 프로젝트를 자동 발견하거나 모듈 경계를 알아서 추론하고, 관계없는 새 세션에 기록을 자동 주입하는 기능은 포함하지 않습니다. 상주 감시·DB·백그라운드 에이전트도 추가하지 않았습니다.

## 보존 확인 범위

기존 이력 938개의 접두 기록과 계약·실행 설정을 보존했습니다. 처음 보호 대상으로 잡은 818개 파일 중 817개는 바이트까지 같았고, 다른 작업의 UI 산출물 요약·갱신 시각 변경 한 건은 따로 검토했습니다. 설정이나 기준을 복원하지 않았습니다. 초기 캡처에서 빠진 기존 CLI 시험 프로필 캐시는 런타임 자동 백업과 추가 대조했으며 확인된 차이는 `oauthAccount.profileFetchedAt`뿐이었습니다. 정리 시각 파일의 변경 전 바이트는 없어 프로필 전체가 바이트 동일하다고 주장하지 않습니다. 정확한 범위와 첫 실패 기록·측정 한계는 검증 결과에 명시했습니다.

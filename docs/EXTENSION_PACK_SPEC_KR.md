# CALF 확장팩 공통 규격

[English](EXTENSION_PACK_SPEC.md) · [스키마·예제](../specs/pack-v1/README.md) · [처음으로](../README_KR.md)

**규격 0.1.0 · 초안 · 2026-11-07.** FFmpeg·모션 보정·Repository 팩이 함께 따를 계약입니다. [첫 로컬 구현](PACK_MANAGER_KR.md)은 FFmpeg 후보의 메타데이터·호환 확인·잠금 정보·준비·검수·활성화·중단 후 복구를 지원합니다. 범용 의존성 해석기·다운로드 등록소·Workbench 팩 UI는 이번 프리뷰 범위 밖입니다. 기존 배포판과 계약은 바꾸지 않습니다. JSON 스키마에 맞는다는 이유만으로 설치·실행을 허용하지 않습니다.

## 1. 작은 공통 코어와 독립 버전

코어는 감독 실행·시도·네이티브 증거·채택을 담당합니다. 팩은 공개 인터페이스로 분야별 입력 규칙, 고정된 도구 어댑터, 독립 검사, 복구와 사용법을 제공합니다. CLI·SDK·MCP는 같은 처리 기능을 공유합니다. MCP는 선택적인 호출 창구이며 실행 권한을 부여하지 않습니다. 팩마다 실행 엔진이나 에이전트 스케줄러를 새로 만들지 않습니다.

| 항목 | 규칙 |
| --- | --- |
| 팩 식별자 | 소문자와 점으로 된 고정 `id`. 사용자 경로나 계정은 넣지 않습니다. |
| 팩 버전 | SemVer `MAJOR.MINOR.PATCH`. 사전 배포·빌드 표기를 허용합니다. 배포한 `(id, version)`은 항상 같은 패키지 바이트를 뜻하며, 파일이 바뀌면 새 버전이 필요합니다. |
| 호환성 변경 | 입력·출력·부작용·권한·복구 의미가 깨지면 major, 호환되는 기능 추가는 minor, 호환되는 수정은 patch를 올립니다. 0.x에서도 변경 내용을 기록합니다. |
| 스키마 | `calf.extension-pack.v1`. 아직 실제 제품에서 고정된 형식은 아닙니다. 채택 이후 해석·의미가 깨지는 변경은 새 스키마 major로 분리합니다. 모르는 필수 필드·기능은 활성화를 막습니다. |
| 배포 단위 | 팩·모노레포/Python 배포본·SDK·코어 버전은 별개입니다. 기존 FFmpeg 0.1.0의 이름·파일·해시를 소급 변경하지 않습니다. |
| 성숙도 | `experimental`, `preview`, `stable`. 이 표시는 검증을 대체하지 않습니다. 참조 매니페스트는 `availability: reference`이며 배포판으로 설치할 수 없습니다. |

초안에 `availability: candidate`를 추가했습니다. experimental/preview 산출물을 준비·로컬 검수한 뒤 실험용임을 명시적으로 선택해 활성화할 수 있습니다. 안정 릴리즈 검증을 통과했다고 표시하지 않으며, 기존 설계 예제 3개는 계속 설치 불가 참조 자료로 유지합니다.

새 팩에 맞춰 기존 작업을 고치지 않습니다. 사전 배포판은 사용자가 의도적으로 선택해야 하며, preview→stable이나 코어 에디션 간 전환을 자동으로 수행하지 않습니다.

## 2. 실행 모드별 의존성

의존성을 한 번 선언하고 각 모드에서 필요한 항목만 참조합니다. **선택한 모드에 필요한 것만** 이미 설치된 로컬 환경이나 명시적으로 준비한 의존성에서 찾습니다. 전역 패키지 환경을 재구성하거나, 목록을 보기 위해 모든 팩을 import하지 않습니다.

| 팩·초기 모드 | 의존성과 코어 | 범위 |
| --- | --- | --- |
| `calf.media.ffmpeg` / 감독 씬 작업 | Python 3.10+, SDK 0.2.1, 필요한 인코더·필터가 있는 FFmpeg/ffprobe, Harness 1.8.7 **또는** Workbench 1.9.2 | 기존 씬 후보·기술 검사·씬 선택 |
| `calf.media.motion-patch` / 감독 패치 보정 | 분리된 NumPy/OpenCV 환경, Python, SDK, 호환 코어 | 작은 배경 패치 정합을 계획합니다. FFmpeg는 비교 프리뷰 모드를 따로 선택할 때만 필요합니다. Nuke는 선택적인 후속 작업 도구입니다. |
| `calf.repository.local-git` / 독립 탐색 | Python, 필요한 기능이 있는 Git, 뷰어용 브라우저. **코어·SDK·FFmpeg·모델은 불필요** | 읽기 전용 수집·탐색·내보내기 계획. CALF 증거 연동은 이후의 선택 모드입니다. |

의존성에는 ID·종류·숫자 버전 범위·필수 기능을 적습니다. 범위는 `[minInclusive, maxExclusive)`이며, 정수 버전 요소를 비교하고 부족한 자리는 0으로 채웁니다. 첫 형식은 안정 버전의 숫자 구성만 받습니다. 임의의 pip/npm 조건식·사전 버전 매칭·셸 표현식은 받지 않습니다. 정규화한 버전과 원래 벤더 표기를 함께 보존합니다. 해석할 수 없는 버전은 `UNKNOWN`으로 남기며, 생태계 메타데이터·기능 확인이나 명시적인 형식 개정을 사용합니다.

Python 라이브러리는 네이티브 모듈을 import하기 전에 선택한 환경의 배포 메타데이터를 확인합니다. 실제 설치 버전·배포본/휠 해시는 로컬 잠금 정보에 고정합니다. 넓은 버전 범위는 검토할 후보 범위이며, 그 안의 모든 버전을 검증했다는 뜻은 아닙니다. `libx264`·`blackdetect`, Git SHA-256 객체·지연 fetch 차단 같은 기능도 따로 확인해야 합니다.

브라우저처럼 기능 기준으로 선택하는 앱은 `versionPolicy: capability-only`와 필수 기능을 선언합니다. 서로 다른 브라우저에 공통 최저 버전을 임의로 붙이지 않습니다. 실제 브라우저·버전을 기록하고 검증한 조합만 지원 대상으로 표시합니다. Repository 조회·오프라인 내보내기에는 브라우저가 필요하지 않으며 뷰어 모드에서만 요구합니다.

코어는 에디션별 범위를 대안으로 선언합니다. FFmpeg 참조 범위는 우선 Harness `>=1.8.7 <1.8.8`, Workbench `>=1.9.2 <1.9.3`으로 제한합니다. 새 근거가 있어야 넓힐 수 있습니다. 모든 1.8.x/1.9.x나 새 SDK의 호환성을 가정하지 않습니다. 감독 모드는 공개 프로토콜과 등록된 어댑터를 사용합니다. 지원되는 읽기 전용 확인 방법이 있으면 사용하고, 없으면 검증된 정확한 바이너리로 한정합니다. 확인 API를 임의로 만들거나 비공개 SQLite를 읽거나 발견 과정에서 시험 작업을 생성하지 않습니다.

호환 결과는 `COMPATIBLE`·`INCOMPATIBLE`·`UNKNOWN`으로 구분하고, 독립 모드의 불필요한 코어는 `NOT_REQUIRED`로 표시합니다. 의존성 누락, 미검증 OS·코어 조합, 프로토콜 근거 부재를 준비 완료로 표시하지 않습니다. 미확인 상태를 명시한 실험 모드는 의도적으로 선택할 수 있으나, 정식 검증이나 새로운 실행 효과에 대한 승인이 되지는 않습니다.

## 3. 패키지 구성과 로컬 잠금 정보

새 배포판의 제안 구조입니다.

```text
pack.json                  UTF-8 선언형 매니페스트, 최대 64 KiB
FILES.sha256               자기 자신을 제외한 패키지 파일 목록·해시
qualification.json         플랫폼·검사 범위·결과·근거 신원
docs/                      영·한 사용법과 한계
...                        팩 코드·정적 자산·제한된 예제
```

릴리즈 외부 SHA256SUMS는 압축파일과 별도 검증 자료를 포함합니다. 해시는 파일의 동일성을 확인할 뿐 배포자의 신뢰성을 보증하지 않습니다. 선택한 배포처·게시자도 확인하고, 인증된 전달 경로나 서명이 있으면 기록합니다. 참조 자료에 가짜 서명을 붙이거나 임시 해시를 검증 근거로 사용하지 않습니다.

향후 호스트는 준비된 팩을 검사한 뒤 불변 팩 파일·사용자 소스 밖에 **로컬 잠금 정보**를 기록합니다.

- 팩 ID·버전, 매니페스트·압축파일·파일 목록의 SHA-256
- 선택 모드·기능, 필요할 때 코어 에디션·버전·실행 파일 해시
- 실제 인터프리터·SDK·어댑터 파일, 도구 해시, 라이브러리 잠금 정보와 기능 확인 결과
- 입출력·검사 스키마와 프로필의 버전·해시, 허용 경로·네트워크 정책·실효 자원 한도
- 검증 영수증 참조, OS·아키텍처·확인 시각과 미확인 항목

새 작업의 공개 계약·등록에도 이 신원을 연결합니다. 기존 작업은 원래 계약과 참조를 유지합니다. 과거 저널을 고치거나 시도를 초기화하거나 새 도구로 자동 대체하지 않습니다. 선택한 파일 해시는 모든 OS·간접 라이브러리를 증명하거나 파일시스템 격리를 제공하지 않습니다.

인증정보·기존 기록·수집 소스·영상·호스트별 경로·개인 설정은 배포 파일에 넣지 않습니다. 절대 로컬 경로는 비공개 잠금 정보에만 둘 수 있습니다. 코어·SDK·외부 도구는 기본 동봉 대상이 아니며, 재배포 시 해당 라이선스와 크기를 따로 검토합니다.

## 4. 설치·활성화·업데이트

첫 FFmpeg 전용 구현의 명령은 [로컬 팩 설치·업데이트 프리뷰](PACK_MANAGER_KR.md)에 설명합니다. 설치 훅이나 자동 의존성 다운로드는 제공하지 않습니다.

1. **메타데이터 확인:** 팩 import·설치 스크립트 실행 없이 크기가 제한된 JSON을 읽습니다. 선택 모드의 의존성과 실행 효과를 함께 보여줍니다. 기존 승인을 존중하며 파일별 확인 절차를 새로 만들지 않습니다.
2. **새 버전 준비:** 출처·압축파일 신원을 확인하고 팩 저장소와 같은 파일시스템의 새 비공개 임시 폴더에 풉니다. 설치된 버전 위에 풀지 않습니다.
3. **파일 목록 검사:** 절대·상위 이탈 경로, 심볼릭/하드 링크·특수 파일, 중복·대소문자 충돌, Windows 예약 이름·ADS, 추가·누락·변조 파일을 거부합니다. 초기 설치 한도는 압축 64 MiB·해제 256 MiB·일반 파일 4,096개·깊이 16단계입니다. 호스트의 더 엄격한 한도를 우선합니다. 팩 파일의 설계 한도이며 영상 작업 한도나 메모리 실측값은 아닙니다.
4. **선택 모드 확인:** 로컬 의존성과 플랫폼 근거를 조사하고 누락·미확인을 남깁니다. 모델·도구 다운로드, PATH·셸 프로필·전역 Python·MCP 클라이언트·코어 설정·OS 서비스 변경을 자동으로 수행하지 않습니다.
5. **격리된 설치 검사:** 새 임시 자료·기록·프로젝트에 합성 입력으로 선언된 검사를 수행합니다. 실제 프로바이더 호출·외부 전송·사용자 데이터 변경은 설치 확인 작업이 아닙니다. 고정 검사에도 기존 호스트 실행 권한이 필요합니다.
6. **새 작업에 활성화:** 신원을 재확인한 뒤 새 잠금 정보를 기록·flush하고, 호스트 잠금 아래 작은 활성 버전 포인터를 원자적으로 교체합니다. 이전 포인터·버전은 보존합니다. 원자적 교체나 저장 완료를 확인할 수 없으면 중단된 상태로 남기고, 현재 상태를 조회한 뒤 다음 변경을 판단합니다.

새 작업만 새 활성 버전을 사용합니다. 기존 작업은 보존된 코어·어댑터·의존성·기록으로 이어갑니다. 업데이트를 이유로 워커를 중단하거나, 미해결 네이티브 예약을 해제하거나, 같은 실행을 다시 제출하지 않습니다. 기존 계정·인증정보의 소유 위치도 유지합니다.

첫 도입은 추가 방식으로 합니다. 향후 새 배포판에 메타데이터와 새 등록을 제공하되 기존 FFmpeg 압축파일·등록·고정 계약은 수정하지 않습니다. 기존 `calf-media` 경로도 유지합니다. 지금 공통 Python 배포본이나 진입점을 바꿀 필요는 없습니다.

## 5. 검수와 완료 판정

다음 세 결과를 구분합니다.

| 단계 | 통과 근거 |
| --- | --- |
| 패키지·호환성 | 전체 파일 해시, 선택 모드 의존성·프로토콜 확인, 격리 설치 검사, 정확한 플랫폼 근거 |
| 작업 실행 | 감독 작업의 현재 네이티브 `verified`·`SATISFIED`, 입력·어댑터/프로필·후보 매니페스트·독립 검사 영수증의 결속. 정상 종료나 MCP 연결만으로는 부족합니다. |
| 분야별 수락 | 정확한 후보와 보존 범위에 대해 필수 기술·품질 검사 및 고정된 채택 조건 충족. 계약상 필요하면 사용자 수락도 별도로 받습니다. |

검증 기록은 `PASS`·`FAIL`·`UNKNOWN`·`NOT_RUN`·이유를 적은 `N/A`를 사용합니다. 검사 ID·요청/관측 범위·도구/코어 해시·플랫폼·출처를 남깁니다. 재사용 근거는 원래 신원·시각을 유지합니다. 한 OS의 통과를 다른 OS로 복사하거나 목표치를 실측값으로 바꾸지 않습니다. 새 팩 설치 규격의 검증과 기존 FFmpeg 실행 검증도 별개입니다.

FFmpeg는 기존 미디어 검사와 씬 프로젝트의 비교 후 교체 검사를 유지합니다. 모션 보정은 정합에 쓰지 않은 평가점, 수정 의도, 마스크 밖 원본 픽셀, 시간적 안정성, 새 왜곡 여부를 확인해야 하며 지원하지 않는 장면까지 통과했다고 주장하지 않습니다. Repository는 HEAD·index·작업 파일·커밋의 정확한 신원, 범위·부분 결과 표시, 조회 전후 원본 보존을 확인합니다. 독립 뷰어 결과를 네이티브 CALF 검증이라고 표시하지 않습니다.

실패한 검사를 빼거나 조건을 낮춰 통과시키지 않습니다. 입력·도구·검사·후보가 달라지면 해당 현재 증거를 무효화하되 과거 영수증은 보존합니다. 기본은 요청 에이전트 하나와 기존 네이티브 실행 범위별 워커 하나입니다. 병렬 스케줄러를 추가하지 않습니다.

## 6. 복구와 데이터 보존

| 상황 | 처리 기준 |
| --- | --- |
| 의존성 누락·변경 | 해당 모드·새 작업을 막고 이전 잠금 정보·작업을 보존합니다. 신뢰된 동일 의존성을 명시적으로 복구하거나 새 버전을 새 작업에 등록합니다. 전역 설정을 자동 수리하지 않습니다. |
| 준비·활성화 중단 | 최초 실패와 준비 기록을 남깁니다. 잠금 아래 활성 포인터·파일을 확인하며 무작정 재실행·덮어쓰지 않습니다. |
| 응답 유실·시간 초과 | 같은 네이티브 요청을 조회·대조합니다. 소비한 시도와 미해결 예약을 보존합니다. 시간 초과로 실패를 확정하지 않습니다. |
| 취소 | 실제 종료와 소유 프로세스 정리를 확인합니다. 취소 요청·PID 부재·창 닫힘만으로 종료를 단정하지 않습니다. 확인할 수 없으면 UNKNOWN입니다. |
| 팩 버전 복귀 | 보존된 팩·잠금 정보를 현재 호스트에서 재확인하고 **다음 작업용**으로 선택합니다. 과거 작업·프로젝트·사용자 데이터를 되돌리는 기능이 아닙니다. |
| 산출물 복원 | 명시한 분야별 경로와 현재 신원 검사만 사용합니다. FFmpeg는 보존 씬을 선택할 수 있습니다. 모션 패치 복원은 아직 검증되지 않았습니다. Repository는 보존 수집본을 다시 열며 소스 저장소에 checkout/reset하지 않습니다. |
| 제거·정리 | 먼저 새 사용을 막습니다. 실행·미해결·재개 가능한 작업이 참조하는 버전·환경은 보존합니다. 명시적 정리에서 미참조 코드·캐시만 제거하며 기록·후보·계약·인증정보·개인 설정을 자동 삭제하지 않습니다. |

현재 Universal Work v1은 현재 후보를 채택하며 이전 채택본의 일반 선택 API를 제공하지 않습니다. FFmpeg의 씬 복원은 별도 확장 계약입니다. 팩 버전 복귀·네이티브 재검사·분야별 복원을 같은 기능으로 표시하지 않습니다.

기록·보존 후보·사용자 설정은 팩 버전 폴더 밖에 둡니다. 업데이트 검증 시 허용된 기존 데이터의 스냅샷·해시를 확인하고 원래 형식·경로를 유지합니다. 개인 기본값은 새 작업의 입력만 제안할 수 있으며 기존 계약·프로필·승인 범위가 우선합니다. v1에 설정 이전은 포함하지 않습니다. 향후 필요하면 원본을 보존한 별도의 명시적·가역적 이전으로 준비합니다.

## 7. 경량화·로컬화 기본값

- 작은 매니페스트로 목록을 읽고 선택 모드의 모듈만 불러옵니다. Git 탐색·FFmpeg 전용 실행에 OpenCV·NumPy를 올리지 않습니다.
- 필요할 때 실행합니다. MCP는 포그라운드 stdio, 뷰어는 인증된 포그라운드 루프백 연결을 사용할 수 있습니다. 세션 종료 시 소유 리스너·프로세스를 정리합니다. 상주 팩 데몬·자동 시작 서비스를 만들지 않습니다.
- 선택한 파일·페이지만 읽고 미리보기·로그·캐시 크기를 제한하며 큰 산출물은 스트리밍합니다. 증거는 디스크의 참조로 보관하고 미디어·전체 이력을 상시 적재하지 않습니다. 소유한 미참조 캐시만 비웁니다. 원본 증거는 캐시가 아닙니다.
- 작업 시간·출력 한도를 선언하고 기존 자원 페이더를 재사용합니다. 자원 압박 시 선택적인 프리뷰·내보내기를 늦추되 필수 검사는 유지합니다. 스레드 수 설정·폴링은 커널 CPU·메모리 할당량을 보장하지 않습니다.
- 세 팩은 모델·프로바이더 계정을 필수로 요구하지 않습니다. 발견 과정에서 의존성 다운로드·네트워크 확인을 수행하지 않습니다. Repository 뷰어는 loopback, 내보내기는 오프라인을 기본으로 합니다. 향후 외부 모드는 목적지·전송 자료 정책을 명시하고 인증정보는 패키지 밖에서 참조합니다.
- 실행이 로컬이어도 클라우드 에이전트가 MCP 결과를 받을 수 있습니다. 전송 범위는 호스트가 선택합니다. 로컬 파일 처리만으로 자료가 외부에 나가지 않는다고 보장하지 않습니다.
- UI는 영어 기본·한국어 안내를 제공하며 텍스트·경로·내용은 UTF-8/CJK를 보존합니다. OS에서 만들 수 없는 이름은 이식성 제한으로 기록합니다.

## 8. 공통 릴리즈 합격 기준

기준·선택 모드·플랫폼별 근거를 따로 기록합니다. 로컬 FFmpeg 프리뷰는 설치·의존성 고정·네이티브 작업·중단 복구를 시험하지만 모든 팩·기준을 PASS로 승격하지 않습니다. 스키마 검증은 별도이며, 실행하지 않은 분야·플랫폼·릴리즈 검사는 NOT_RUN으로 남깁니다.

| ID | 필수 확인 |
| --- | --- |
| PK01 | 엄격한 JSON·스키마, 중복 없는 ID, 올바른 범위·참조. 중복 키·알 수 없는 보안 필드·참조 자료의 배포판 설치를 거부 |
| PK02 | 변조 압축파일·목록 불일치·경로 이탈·링크·이름 충돌·한도 초과를 활성화 전에 거부하고 이전 활성 버전 유지 |
| PK03 | 도구/SDK 누락·미지원 코어/플랫폼·미확인 기능·오프라인을 명시. 암묵적 설치·네트워크·설정 변경 없음 |
| PK04 | 독립 Repository가 SDK·미디어/네이티브 CV·모델을 import하지 않으며 선택 모드 의존성만 로드 |
| PK05 | 새 폴더 설치 검사가 설치 파일 신원에 결속되고 종료·취소 후 소유 리스너·자식 프로세스 정리 |
| PK06 | 포인터 교체 전후 중단·응답 유실·동시 활성화에서 혼합 버전 작업이 생기지 않고 최초 실패 보존 |
| PK07 | 기존 작업 준비·실행·미해결 중 업데이트해도 원래 신원·시도에서 재개. 새 작업만 새 버전 선택하며 중복 실행 없음 |
| PK08 | 팩 복귀·제거 시 참조 중인 버전·잠금 정보·기록·계약·설정·인증정보·분야별 승인 보존 |
| PK09 | 입력·검사·도구·후보 변경이나 검사 없는 정상 종료가 채택을 허용하지 않음. 거부된 호출에 미승인 효과 없음 |
| PK10 | FFmpeg 씬 불변조건, 모션 품질·범위, Repository 읽기 전용·버전 기준 통과. 미지원 복구 기능 비활성 |
| PK11 | 영·한 안내·CJK 경로·새 폴더 설치·오프라인·정확한 코어/SDK/어댑터 신원을 실제 macOS·Windows·Linux의 선언 범위에서 확인 |
| PK12 | 게시처별 실제 다운로드·파일 해시·소스 신원 일치. 제외·재사용 근거 명시. 스키마·연결 확인을 실행 전체 검증으로 취급하지 않음 |

릴리즈 승격은 주장하는 플랫폼·모드별 PK01–PK12와 팩별 합격 기준을 함께 충족해야 합니다. 이번 설계 작업에 메모리·장시간 시험은 요구하지 않습니다. 이후 실측값은 자원 설계 한도와 구분해 실제 범위대로 보고합니다.

## 9. 적용 순서

1. [설치 불가 참조 매니페스트 3개](../specs/pack-v1/README.md)를 현재 팩 계획과 검토합니다. 모션 품질 실험과 Repository P0 구현은 별도로 유지합니다.
2. 팩 import·네이티브 실행 의미 변경 없이 작은 메타데이터/호환 확인기와 로컬 잠금 정보 기록기를 구현합니다.
3. 버전별 준비·활성화·복구를 연결하고 격리된 자료로 공통 합격 기준을 확인합니다.
4. **새** 팩 릴리즈부터 검증된 메타데이터를 붙입니다. Workbench는 같은 메타데이터·기록을 보여주며 UI에 별도 엔진·관리기를 만들지 않습니다.

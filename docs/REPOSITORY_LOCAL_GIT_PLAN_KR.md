# CALF Repository Navigator 프로젝트 지도 구현 계획

[English](REPOSITORY_LOCAL_GIT_PLAN.md) · [Git 하위 계층 기준](REPOSITORY_GIT_BACKEND_PLAN_KR.md)

## 제품의 기준

사용자가 제시한 START_HERE 화면의 경험을 다른 프로젝트에 적용하는 무료 CALF 확장팩입니다. 프로젝트 형상을 데이터로 정리하고, 포털·관계 지도·맵 아래 상세 패널로 탐색하게 하는 템플릿과 생성기를 만듭니다. GitHub·GitLab·Local Git은 프로젝트 형상과 버전의 데이터 원천입니다.

주요 탐색 흐름은 **프로젝트 → 기능·정의·문서 → 모듈·파일·심볼 → 전후 연결·변경 영향 → 코드·Diff → 검증 근거**입니다. 커밋 목록과 브랜치 그래프를 제품의 중심 화면으로 만들지 않습니다. 이미 작성한 Git 읽기 코드는 정확한 원문·버전·출처 확인에 사용합니다.

사용자는 프로젝트 폴더를 한 번 선택해 등록합니다. 등록한 범위의 구조·소스·문서 연결을 자동 수집하며, 갱신은 사용자가 명시적으로 실행합니다. PC/계정 전체를 스캔하거나 자동 등록하지 않습니다. Local Git으로 시작하고 GitHub·GitLab의 PR/MR/CI 연결은 뒤에 붙입니다.

## 첫 사용 경험

1. 등록한 프로젝트의 시작 포털이 열립니다. 상단에서 개요·기능·문서·소스 관계·검증 자료로 이동합니다. 없는 자료는 미연결 상태로 표시합니다.
2. 관계 지도에서 파일이나 심볼을 선택합니다. 들어오는 연결·나가는 연결과 분석된 범위의 다단계 관계를 확대·이동하며 탐색합니다.
3. 전체 맵 박스 아래에서 설명·정의·소유 범위·출처·연결 기능을 확인합니다.
4. 같은 패널에서 정확한 버전의 코드·줄번호·관계가 발견된 위치·Diff·에디터 링크를 사용합니다.
5. 이전 선택·고정 비교·필터·단계·확대 상태를 복원하고 프로젝트 지도를 HTML/JSON으로 보존할 수 있습니다.

## P0 형상과 근거 계약

`project`, `feature`, `term`, `document`, `module`, `file`, `symbol`, `external_interface`, `check/evidence`를 구분합니다. 각 개체에 ID·정의/설명·출처·버전·분석 상태를 둡니다. 관계는 `CONTAINS`, `DOCUMENTS`, `IMPLEMENTS_FEATURE`, `IMPORTS`, `STATIC_CALL`, `REFERENCES_INTERFACE`, `TEST_REFERENCE`, `SUPPORTED_BY` 등으로 명시합니다.

관계의 근거에는 파일·심볼·줄 범위·commit/blob 또는 수집 SHA·분석 방법·버전을 둡니다. 정적 연결은 실행 성공이나 기능 전체 검증을 의미하지 않습니다. 역방향 정적 도달성은 변경 영향 후보이며 실제 런타임 영향 확정이 아닙니다. 기존 CALF 판정은 공식 SDK가 제공하는 범위와 파일 버전에만 연결합니다.

기능의 의미와 용어 정의는 확인된 문서·주석·사용자 매핑에서 가져옵니다. 임의의 함수 이름으로 제품 기능을 지어내지 않습니다. 기능 설명이 없으면 구조 지도는 자동 생성하되 기능 연결은 미등록으로 표시합니다. 첫 프로젝트 설정에서 명시적 기능·용어·문서·코드 매핑을 받을 수 있게 합니다. 설정과 생성물은 원본 저장소 밖에 둡니다.

첫 분석기는 Python 표준 AST로 정의·import·해석 가능한 정적 호출을 수집합니다. 파일을 import하거나 실행하지 않습니다. 동적 호출·alias·해석 불가능한 연결은 unresolved로 남깁니다. 다른 언어는 파일·문서·버전 탐색을 제공하되 심볼/호출 분석 미지원 상태를 표시합니다. Rust·JS/TS 등 언어 분석은 별도 어댑터로 확장하며 기존 VibePackr의 보존 GAPE 그래프를 새 저장소 분석으로 복제하지 않습니다.

## 구현 순서

| 단계 | 산출물과 종료 조건 |
| --- | --- |
| P0 | 프로젝트 형상 schema, 관계·출처·분석 coverage, 등록 계약을 고정합니다. Git 읽기 8개 fixture 결과는 하위 계층 근거이며 지도 구현 완료가 아닙니다. |
| P1 | 프로젝트 inventory·문서 연결·기능/용어 매핑·Python AST 어댑터를 만듭니다. 실제 파일·심볼·줄·해석 상태와 대조합니다. |
| P2 | 관계 그래프·전후 연결·다단계 탐색·영향 후보를 만듭니다. 각 edge의 실제 출처와 분석 범위를 독립 fixture에 대조합니다. |
| P3 | 범용 START_HERE 템플릿과 생성기, 상단 메뉴·지도·맵 아래 inspector·정의/설명·코드·Diff·에디터를 연결합니다. |
| P4 | 버전별 형상 수집·새로고침·이력/pin/bookmark·오프라인 HTML/JSON을 연결합니다. Git 버전 정보는 하단 근거로 사용합니다. |
| P5 | 실제 플랫폼·UI·포장·원본 보존·기존 FFmpeg regression을 검증하고 지원 범위를 영한 문서로 기록합니다. |

실시간 소스 탐색은 사용자가 연 동안의 foreground loopback 뷰어로 제공하고, 보존본은 서버 없이 열리는 정적 포털로 내보냅니다. 에디터는 사용자 클릭으로 열고 현재 작업 파일과 읽기 전용 수집 사본을 구분합니다. 읽기·중단·한도·외부 실행 차단 기준은 하위 Git 문서를 따릅니다. Git 작업 실행 UI는 추가하지 않습니다.

| ID | 합격 조건 |
| --- | --- |
| RN01 | 새 프로젝트 등록 후 기능·문서·소스 관계 중심의 포털이 생성되고 VibePackr 고유 경로·데이터가 없음 |
| RN02 | Python fixture의 파일·중첩 심볼·정의 줄·docstring을 독립 기대값과 대조; 프로젝트 코드 실행 0 |
| RN03 | 해석된 import·정적 호출의 방향·대상·발견 줄이 일치하고 동적/미지원 연결을 확정 edge로 만들지 않음 |
| RN04 | 기능·용어 매핑의 출처·범위·누락을 표시; 미등록 정의나 runtime 성공을 생성하지 않음 |
| RN05 | 들어옴/나감·1/2/3단계/분석된 전체·cycle·diamond·고립 노드를 누락/중복 없이 처리; coverage와 표시 범위를 구분 |
| RN06 | 노드/edge 선택 시 맵 아래 설명·정의·정확한 코드 줄·관계 출처가 함께 바뀜 |
| RN07 | 변경 영향은 역방향 정적 도달성 후보로 표시하며 실행 검증·권한·CALF 성공과 혼동하지 않음 |
| RN08 | HEAD/index/작업 파일의 코드·Diff·SHA가 정확하고 stale 파일을 현재 수집본으로 표시하지 않음 |
| RN09 | 탐색 이력·고정 비교·필터·코드 줄·확대/중심·새 hash 이동을 함께 복원; 키보드 초점 유지 |
| RN10 | 원본 저장소 없이 offline 포털을 열 수 있고 누락 원문·로컬 경로·인증·CALF 기록을 임의 포함하지 않음 |
| RN11 | 1440/390/320px·영한 UI·코드 독립 스크롤·에디터 경로/줄·console 오류를 실제 브라우저로 확인 |
| RN12 | refs/index/설정/소스 및 기존 FFmpeg·CALF 보존 대상 불변; helper/필터/네트워크 암묵 실행 0; 한도/취소 cleanup 확인 |

하위 Git의 LG01–LG28은 위 경험의 신뢰성과 배포를 위한 추가 기준입니다. 지도 기능 대신 LG 항목만 통과시켜 제품 완료로 표시하지 않습니다. 미실행 플랫폼·언어·기능은 NOT_RUN/UNSUPPORTED/UNMAPPED로 남기며 실제 검증한 범위만 공개합니다. 기존 FFmpeg 확장과 CALF 기록을 수정하지 않습니다.
